# IAM Access Review Engine

A quarterly user-access review, automated. The Python engine reconciles a directory export against the HR roster (who works here) and an approved RBAC matrix (what each role gets), then produces a severity-ranked findings file and an analyst report with remediation actions and root-cause themes.

All identities are synthetic, generated by a seeded script so every run is reproducible.

## What it checks

| Check | Finding | Severity |
| :--- | :--- | :--- |
| C1 | **Orphaned account:** terminated in HR, still enabled in the directory | CRITICAL |
| C2 | **Privilege creep:** member of groups outside the role's RBAC entitlement | HIGH if a privileged group, otherwise MEDIUM |
| C3 | **Privileged account without MFA** | HIGH |
| C4 | **Unowned service account:** no registered owner | MEDIUM |
| C5 | **Dormant account:** active, no logon in more than 90 days | MEDIUM |

Privileged groups are `GRP_Domain_Admins`, `GRP_Workstation_Admins`, and `GRP_EHR_Orders`. The review procedure, JML lifecycle mapping, and HIPAA / NIST CSF 2.0 control mapping for each check are in [`docs/access_review_procedure.md`](docs/access_review_procedure.md).

## Sample results

The included data set has 62 directory accounts, 60 employees, and 7 roles. A run produces 17 findings across 17 accounts:

| Check | Findings |
| :--- | :--- |
| C1 Orphaned account | 3 |
| C2 Privilege creep | 5 (2 HIGH, 3 MEDIUM) |
| C3 Privileged without MFA | 3 |
| C4 Unowned service account | 2 |
| C5 Dormant account | 4 |

Example lines from [`output/access_review_report.md`](output/access_review_report.md):

> **lvargas2** (Logan Vargas, IT Administrator) - Terminated 2026-06-10 but account still enabled (21 days exposed). *Action:* Disable immediately, revoke sessions/tokens, audit activity since termination date
>
> **akowalski6** (Alex Kowalski, Registration Clerk) - Groups outside 'Registration Clerk' entitlement: GRP_Domain_Admins. *Action:* Confirm business need with manager; remove excess membership or document exception

The report ends with root-cause themes that tie findings back to the joiner-mover-leaver process, such as a deprovisioning gap behind orphaned accounts and missing mover re-provisioning behind privilege creep.

## Run it

Requires Python 3.9+ and pandas.

```bash
git clone https://github.com/elazarf123/iam-access-review.git
cd iam-access-review
pip install -r requirements.txt

python src/generate_identity_data.py   # builds data/*.csv (seeded, reproducible)
python src/run_access_review.py        # writes output/findings.csv and output/access_review_report.md
```

## Remediate orphaned accounts

[`remediation/Disable-OrphanedAccounts.ps1`](remediation/Disable-OrphanedAccounts.ps1) reads the C1 findings and shows what it would disable. It runs as a dry run by default.

```powershell
.\remediation\Disable-OrphanedAccounts.ps1              # dry run
.\remediation\Disable-OrphanedAccounts.ps1 -Execute     # simulated live run
```

The `Disable-ADAccount` call is commented out so the script is safe to run anywhere. Uncomment it only in a lab or an approved change window.

## Project structure

```text
src/generate_identity_data.py        # Builds the synthetic HR roster, directory export, and RBAC matrix
src/run_access_review.py             # Runs checks C1-C5, writes findings and report
data/hr_roster.csv                   # HR source of truth
data/accounts_export.csv             # Directory export: groups, MFA, last logon, owner
data/rbac_matrix.csv                 # Approved role -> group entitlements
output/findings.csv                  # One row per finding, severity-ranked
output/access_review_report.md       # Analyst report with actions and root causes
remediation/Disable-OrphanedAccounts.ps1   # Gated remediation for C1 findings
docs/access_review_procedure.md      # Review procedure and control mapping
Audit-AccessReviews.ps1              # Standalone PowerShell stale/privileged account check
```
