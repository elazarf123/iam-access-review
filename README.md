# IAM Access Review Engine

A Python access review that compares a directory export against the HR roster and an approved role matrix, finding the orphaned accounts, privilege creep, and MFA gaps that auditors look for in a quarterly user-access review.

## Results

Sample run on the included **synthetic** data set (62 directory accounts, 60 employees, 7 roles). The data is generated by a seeded script, so every run gives the same 17 findings:

| Check | What it finds | Severity | Findings |
| :--- | :--- | :--- | :--- |
| C1 | Orphaned account: terminated in HR, still enabled | CRITICAL | 3 |
| C2 | Privilege creep: groups outside the role's entitlement | HIGH (privileged group) / MEDIUM | 5 (2 HIGH, 3 MEDIUM) |
| C3 | Privileged account without MFA | HIGH | 3 |
| C4 | Service account with no owner | MEDIUM | 2 |
| C5 | Dormant account: no logon in 90+ days | MEDIUM | 4 |

Example line from [`output/access_review_report.md`](output/access_review_report.md):

> **lvargas2** (Logan Vargas, IT Administrator) - Terminated 2026-06-10 but account still enabled (21 days exposed). *Action:* Disable immediately, revoke sessions/tokens, audit activity since termination date

## How it works

- [`src/generate_identity_data.py`](src/generate_identity_data.py) builds a synthetic HR roster, directory export, and role-to-group matrix (seeded, reproducible).
- [`src/run_access_review.py`](src/run_access_review.py) runs checks C1–C5 and writes a severity-ranked [`findings.csv`](output/findings.csv) and an analyst [report](output/access_review_report.md).
- The report ends with root-cause themes tied to the joiner-mover-leaver process (for example, a deprovisioning gap behind orphaned accounts).
- [`remediation/Disable-OrphanedAccounts.ps1`](remediation/Disable-OrphanedAccounts.ps1) reads C1 findings and is a dry run by default; the `Disable-ADAccount` call is commented out so it is safe anywhere.
- [`docs/access_review_procedure.md`](docs/access_review_procedure.md) maps each check to HIPAA and NIST CSF 2.0 controls.
- [`Audit-AccessReviews.ps1`](Audit-AccessReviews.ps1) is a small standalone PowerShell version of the stale/privileged-account check on a 4-user sample.

Python 3.9+ · pandas · PowerShell

## Run it

```bash
git clone https://github.com/elazarf123/iam-access-review.git
cd iam-access-review
pip install -r requirements.txt

python src/generate_identity_data.py   # builds data/*.csv
python src/run_access_review.py        # writes output/findings.csv and output/access_review_report.md
```

```powershell
.\remediation\Disable-OrphanedAccounts.ps1            # dry run
.\remediation\Disable-OrphanedAccounts.ps1 -Execute   # simulated live run
```

## What I learned

- An access review is a reconciliation: the value comes from comparing three sources (HR, directory, role matrix), not from any one of them.
- Severity has to reflect the group, not just the mismatch: extra membership in `GRP_Domain_Admins` is HIGH, extra membership in a normal group is MEDIUM.
- Remediation should be gated: a dry run by default, with the destructive call disabled until an approved change window.
